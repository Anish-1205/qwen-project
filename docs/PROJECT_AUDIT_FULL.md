## 1. Executive summary

This is a local, single-user assistant built around `Qwen/Qwen2.5-3B-Instruct`. It has five cooperating capabilities:

1. Qwen conversation through a shared `ConversationOrchestrator`.
2. Hybrid intent routing: deterministic evidence first, Qwen only for unresolved flags.
3. Structured and semantic long-term user memory in `agent_memory.db`.
4. TXT/PDF retrieval-augmented generation through `documents.db` and `knowledge/`.
5. A small production-path tool layer with a calculator, die roller, and random integer generator.

The current architecture is coherent and well covered by focused unit tests. The largest remaining risks are missing dependency metadata, sensitive full-context logs, a misleading web memory class name, incomplete web upload validation, heuristic routing limits, and the absence of a current end-to-end real-model regression run.

The previous audit was materially stale. It incorrectly described tool calling as experimental-only, said there were no automated tests, referenced experiment and verification files at old paths, reported obsolete database counts, and treated already-fixed memory/document-budget bugs as current.

## 3. Architecture

```text
chat.py / infer.py / webapp.py
              │
              ▼
   ConversationOrchestrator
      │        │        │
      │        │        ├── ToolManager ──► calculator / roll_die / random_number
      │        │
      │        ├── DocumentIndex ──► documents.db ──► knowledge/*.txt|pdf
      │
      ├── OfflineMemoryManager ──► agent_memory.db
      │
      └── Qwen2.5-3B-Instruct

BGE-small-en-v1.5 (CPU) is shared by memory and document retrieval in each process.
Web chat history is persisted separately in chat_sessions.db.
```

Intent, memory, document retrieval, session history, and tool execution remain separate concerns. The `documents` package still imports `DocumentRetrievalResult` from `orchestrator.py`, which creates avoidable coupling.

## 4. Turn lifecycle

`ConversationOrchestrator.process_turn()` currently performs:

1. Hybrid intent classification for `memory_read`, `memory_write`, `document_read`, and `general_chat`.
2. Contextual memory-write source resolution when the user says something like “update that.”
3. Memory retrieval only when `memory_read` is true.
4. Document lookup only when `document_read` is true.
5. Dynamic system-prompt construction with only the context actually retrieved.
6. History assembly (`chat.py`/web) or a stateless `[system, user]` turn (`infer.py`).
7. Optional history compression and lowest-ranked document-chunk trimming.
8. Tool-aware Qwen generation:
   - all three approved tool schemas are supplied to Qwen;
   - a normal answer ends the generation path;
   - one parsed tool call is validated and executed;
   - the result or structured validation error is returned to Qwen for a final answer.
9. Assistant-history update when history is enabled.
10. One grounded, structured memory-extraction pass when `memory_write` is true.
11. Retrieval metadata construction and return; the web layer then persists the turn.

`general_chat` is routing metadata, not a generation gate: every turn still generates a reply.

### Model calls per turn

| Call | Condition |
|---|---|
| Semantic intent classification | Deterministic router leaves a flag unresolved |
| Intent repair | First semantic output is malformed |
| History summarization | History exceeds the application threshold and older turns can be summarized |
| Initial tool-aware reply | Always |
| Tool-result follow-up | Qwen emits a parseable tool call |
| Memory extraction | A memory write is routed and its evidence source resolves |

Minimum: 1 Qwen call. A turn using a tool normally uses 2. The theoretical maximum is 6 when classification repair, compression, a tool, and memory extraction all occur.

## 5. Intent routing

`DeterministicIntentRouter` resolves high-confidence profile reads/writes, document cues, general questions, mixed requests, and clear contextual inheritance. Only unresolved flags are delegated to `IntentClassifier`.

The semantic classifier must return a strict four-boolean JSON object. It gets one repair attempt; unresolved flags fall back to the legacy all-true decision if classification fails. Deterministic decisions cannot be overridden by the Qwen result.

The saved real-Qwen smoke artifact reports 13/13 correct final hybrid routes. That artifact predates the latest tool integration and was not rerun in this audit, so it is supporting evidence rather than exact-revision validation.

## 6. Memory system

Memory is intentionally scoped to durable facts about the user. Named third-party graph memory is rejected.

Trusted canonical relations are:

- `name`
- `lives_in`
- `works_in`
- `codes_in`
- `favorite_programming_language`
- `recently_codes_in`
- `prefers_beverage`
- relations beginning with `changed_mind`

### Read path

- Exact relation-aware lookup runs first for safely resolved profile questions.
- Tier 1 is a persistent cache of at most five active facts.
- Tier 2 is semantic search over active archive rows, not a separate table.
- Semantic results require cosine similarity greater than `0.50`; at most two unseen relations are added/promoted.
- Web retrieval sets `retrieval_mutates_cache = False`, so reads do not touch LRU timestamps or promote semantic hits.

### Write path

- Qwen returns one or more `entity | relation | value | fact_sentence` candidates.
- Python canonicalizes relation aliases and requires the entity to normalize exactly to `user`.
- Relation cues, values, first-person grounding, and clause boundaries are checked against the selected user evidence.
- Exact active canonical duplicates are rejected, including a transactional recheck.
- Near-duplicate prose within the same relation uses a `0.96` similarity threshold.
- A new value for the same canonical relation invalidates the older active fact rather than deleting history.

The old duplicate-insert defect is fixed in current code and covered by tests. The live database no longer contains duplicate active canonical relations.

### Live read-only snapshot

| Table/state | Count |
|---|---:|
| `global_archive` rows | 6 |
| Active archive rows | 4 |
| `primary_cache` rows | 4 |
| Active relations | one each: name, lives_in, favorite_programming_language, prefers_beverage |

`ReadOnlyOfflineMemoryManager` remains a misleading name: it suppresses retrieval-side cache writes, but the inherited memory-write pipeline can still persist new facts from web turns.

## 7. Document RAG

```text
knowledge/*.{txt,pdf}
  → recursive discovery and hash comparison
  → TXT decoding or pypdf extraction
  → sentence-aware chunks (350 target tokens, 60 overlap)
  → BGE embeddings
  → documents.db
```

Query flow:

1. Hybrid intent routing decides whether documents are needed.
2. The document router gates retrieval at `0.22`, with a `0.08` keyword boost and filename handling.
3. Chunk retrieval uses cosine similarity `>= 0.55` and returns at most four chunks.
4. Explicit filenames scope retrieval; an unknown named file does not inject semantic decoys.
5. Retrieved source blocks are appended to the system prompt and lowest-ranked blocks can be removed to fit the application budget.

Supported source types are `.txt` and `.pdf`. Scanned PDFs have no OCR fallback.

### Live read-only snapshot

- 9 indexed documents and 9 chunks.
- 5 TXT and 4 PDF files in `knowledge/`.
- No deleted document row remains in the current DB.

The web upload endpoint sanitizes to a basename, but it has no backend size or extension check. Unsupported files can be written to `knowledge/` even though discovery will ignore them.

## 8. Production tool system

Tool calling is now in the shared production orchestrator and therefore applies to `chat.py`, `infer.py`, and `webapp.py`.

| Tool | Contract |
|---|---|
| `roll_die` | Integer `sides`, default 6, range 2–1,000,000 |
| `random_number` | Inclusive integer range; each bound limited to ±1,000,000,000 |
| `calculator` | Arithmetic only: numbers, parentheses, `+ - * / // % **`; input ≤200 characters; absolute exponent ≤1000 |

Safety properties:

- Registry allowlist; unknown names are not executed.
- JSON object parsing and per-field schema validation.
- Unexpected/missing/wrong-type/out-of-range arguments are rejected.
- Calculator uses a restricted Python AST evaluator, not `eval()`.
- Only one tool call is handled per user turn.
- Tool success or failure is logged and passed back to Qwen as a structured tool result.

The tool call/result messages are used only for the immediate follow-up generation; only the final assistant text is appended to normal conversation history.

**Verification:** eight tool-specific unit tests passed, and `chatbot_debug.log` contains historical successful production-path executions of `roll_die` and `calculator`. Current real-Qwen behavior for all tools and adversarial prompts was not rerun during this audit.

The old `experiments/tool_calling_test.py` remains only as historical prototype code. Its `eval()` implementation and six manual prompts do not describe the production tool layer.

## 9. Entry points and model configuration

All entry points load `Qwen/Qwen2.5-3B-Instruct` with 4-bit NF4, double quantization, automatic device placement, and evaluation mode. `BAAI/bge-small-en-v1.5` runs on CPU.

| Entry | History | Compression | Reply generation |
|---|---|---|---|
| `chat.py` | Yes | 1,500-token threshold; keep 2 recent turns | 300 tokens, temp 0.7, top-p 0.9 |
| `infer.py` | No | No | 450 tokens, temp 0.7, top-p 0.9 |
| `webapp.py` | Yes | 1,500-token default; keep 2 | 450 tokens, temp 0.7, top-p 0.9 |

Router generation is deterministic with 120 tokens. Intent classification defaults to deterministic 72-token output. Summarization defaults to 200 deterministic tokens in the current orchestrator.

The 1,500-token value is an application threshold, not a hard model limit. The code can still proceed over budget if memory, current input, or retained history alone is too large.

## 10. Web application and sessions

- FastAPI/uvicorn, bound to `127.0.0.1:8000` under `__main__`.
- Background initialization loads Qwen, BGE, memory, and the document index.
- `generation_lock` serializes all model turns.
- Cookie: `roots_chat_session`, HTTP-only, `SameSite=Lax`.
- Session list/create/read/activate/delete routes are present.
- Document list/upload/delete routes are present.
- The trace panel receives per-turn memory and document retrieval metadata.
- Chat messages accept 1–20,000 characters through Pydantic validation.

The reset endpoint clears only the in-memory `SessionState.messages` and turn counter. Persisted DB messages remain, so reloading the session can reconstruct older history and turn numbers can overlap. This is a current correctness risk.

Live DB snapshot: 1 session and 18 messages, with WAL/SHM files present.

## 12. Logging and privacy

`setup_debug_logger()` creates a UTF-8 `FileHandler` using Python’s default append mode. It clears existing handlers to avoid duplicate handlers; it does not truncate the file. There is no rotation or redaction.

The log can contain full system prompts, user messages, memory facts, document chunks, tool arguments/results, and assistant replies. A Windows PowerShell tail window is launched when possible.

This is acceptable only when the local log is treated as sensitive data.

## 14. Current risk register

### High priority

| ID | Risk | Recommended action |
|---|---|---|
| `DEP-001` | No reproducible dependency manifest | Add a reviewed, platform-aware dependency file/lock strategy |
| `WEB-RESET-001` | Reset preserves DB history while resetting in-memory turn numbering | Define reset semantics and update DB/state atomically |
| `LOG-001` | Full sensitive content is appended without rotation/redaction | Add configurable redaction and rotation |

### Medium priority

| ID | Risk | Recommended action |
|---|---|---|
| `WEB-MEM-001` | “ReadOnly” web memory can still write durable facts | Rename it or explicitly disable writes |
| `WEB-UPLOAD-001` | No backend extension or size validation | Validate extension, content length, and overwrite behavior |
| `CTX-001` | The application budget is not a hard cap | Budget all prompt sections and reject/trim oversized input |
| `TOOL-001` | Unit coverage is strong, but current real-Qwen selection/argument quality is not regression-tested | Add a non-destructive real-model tool smoke suite |
| `ROUTE-001` | Deterministic/context inheritance remains heuristic | Expand tests from observed failures and log ambiguous cases |
| `RAG-001` | Brute-force retrieval and duplicate query embedding do not scale | Cache/reuse query embeddings; add a vector index when corpus grows |
| `SEC-001` | No authentication/CSRF/rate limiting | Keep localhost-only or add controls before network exposure |

### Lower priority

- Consolidate repeated model bootstrap/configuration across entry points.
- Decouple document result types from `orchestrator.py`.
- Decide whether `infer.py` remains supported.
- Add OCR only if scanned-PDF support is required.
