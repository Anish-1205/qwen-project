This file is intentionally a short index so that two long audit documents do not drift independently.

Current headline status:

- `HarnessRunner` is backend-independent and consumes `ModelBackend` through typed generation contracts.
- The declarative registry currently configures Qwen 2.5 3B and SmolLM2 through `TransformersBackend`.
- Qwen retains 4-bit NF4 inference; SmolLM2 remains non-quantized with backend-owned textual tool formatting.
- Tool calling is integrated into the production harness with ten allowlisted, validated tools.
- Model switching and normal application shutdown use the backend lifecycle without Torch/Transformers logic in `harness/` or the web layer.
- The complete deterministic suite passes: 193 pytest tests plus 70 subtests; unittest discovery passes 80/80.
- Dependency pins, rotating content-minimized logs, backend upload bounds, and local-tool root restrictions are implemented.
- The latest recorded live-data snapshot remains in `PROJECT_HANDOFF.md`; it was not reread during the backend migration.
- Current top risks include real-model Qwen/SmolLM2 regression coverage, web reset persistence semantics, prompt hard limits, retrieval scaling, and localhost-only security assumptions.

The workspace is a Git repository with extensive pre-existing uncommitted work. No commit was created for the backend migration.
